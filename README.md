# QR出退勤記録システム

QRコードを使った出退勤記録システムです。オフライン環境のタブレットやスマートフォンでQRコードを生成し、従業員のスマートフォンで読み取ることで出退勤を記録できます。

## システム構成

### 1. QRコード生成ページ（PWA）
- **ファイル**: `index.html`, `qr-generator.js`
- **機能**:
  - PWA対応（オフラインでも動作）
  - Service Workerによるキャッシュ戦略（Stale-While-Revalidate）
  - 出勤/退勤ボタン
  - QRコード自動生成・表示
  - JWT トークン生成（3分間有効）
  - LocalStorageによる設定の永続化
  - 操作ログ表示

### 2. QRコード検証テストページ
- **ファイル**: `test.html`, `test.js`
- **機能**:
  - トークンのデコードと検証
  - パラメータの表示
  - 有効期限チェック

### 3. 出退勤記録サーバー
- **ディレクトリ**: `server/`
- **機能**:
  - トークン検証
  - 初回ユーザー登録
  - Cookie管理
  - ログファイル保存（有効/無効を分離、年月ごと）
  - デバイス管理

## セットアップ

### フロントエンド（QRコード生成ページとテストページ）

#### GitHub Pagesでの公開

1. リポジトリのSettings → Pagesに移動
2. Sourceを「GitHub Actions」に設定
3. または、Branchを選択して公開

#### ローカルでのテスト

シンプルなHTTPサーバーを起動:

```bash
# Python 3を使用
python3 -m http.server 8000

# Node.jsを使用
npx http-server -p 8000
```

ブラウザで `http://localhost:8000` にアクセス

### バックエンド（出退勤記録サーバー）

#### 依存関係のインストール

```bash
cd server
npm install
```

#### デバイスの登録

サーバーを使用する前に、デバイスを登録する必要があります:

```bash
# デバイスの登録
node register-device.js DEVICE001 mypassword123

# 登録済みデバイスの確認
node register-device.js --list
```

#### サーバーの起動

```bash
# 通常起動
npm start

# 開発モード（ファイル変更時に自動再起動）
npm run dev
```

サーバーは `http://localhost:3000` で起動します。

## 使い方

### 1. 初期設定

#### QRコード生成ページ（index.html）
1. ページ下部の設定エリアで以下を入力:
   - **デバイスID**: 一意の識別子（例: DEVICE001）
   - **パスコード**: サーバーに登録したパスコード
   - **サーバーURL**: 記録サーバーのURL（例: http://localhost:3000/record）
2. 「設定を保存」ボタンをクリック

#### サーバー側のデバイス登録
```bash
node register-device.js <デバイスID> <パスコード>
```

### 2. 出退勤の記録

1. **QRコード生成ページ**で「出勤」または「退勤」ボタンをタップ
2. QRコードが表示される（色: 出勤=青、退勤=赤）
3. 従業員がスマートフォンでQRコードをスキャン
4. 初回アクセス時は名前を登録
5. 画面に受付完了メッセージが表示される
6. サーバーのログファイルに記録される

### 3. QRコードの動作

- **有効期限**: 3分間
- **自動消去**: 1分後または手動タップで消去
- **タイマー表示**: 残り時間をカウントダウン表示

### 4. ログの確認

ログファイルは `server/logs/` ディレクトリに保存されます:
- `valid-YYYY-MM.log`: 有効なリクエスト
- `invalid-YYYY-MM.log`: 無効なリクエスト

各エントリには以下の情報が含まれます:
- デバイスID
- 名前
- 出勤/退勤
- タイムスタンプ

## テスト方法

### QRコード検証テストページの使用

1. `test.html` を開く
2. パスコードを入力して保存
3. QRコードをスキャンしてURLにアクセス（`?token=...`）
4. トークンの妥当性と内容が表示される

        └── invalid-YYYY-MM.log

## セキュリティについて

### リスク評価
- パスコードが漏洩しても、記録されるのは出退勤ログのみ
- 情報を抜く機能がないため、漏洩リスクは限定的
- シンプルなパスコードで運用可能（電話で伝えられる程度）

### 推奨事項
- HTTPS通信を使用（本番環境）
- パスコードは定期的に変更
- ログファイルへのアクセス制限

## トラブルシューティング

### QRコードが生成されない
- 設定がすべて入力されているか確認
- ブラウザのコンソールでエラーを確認
- パスコードがサーバーに登録されているか確認

### トークンが無効と表示される
- デバイスIDとパスコードが一致しているか確認
- トークンの有効期限（3分）が切れていないか確認
- サーバー側にデバイスが登録されているか確認

### オフラインで動作しない
- Service Workerが正しく登録されているか確認
- ブラウザのデベロッパーツールでService Workerの状態を確認
- キャッシュが正しく保存されているか確認
